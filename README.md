# Case I by Matvey Kvasov

### Кейс 1: скрипт на Node.js, обращающийся к внешнему REST API (fetch + async/await), обработка JSON и ошибок; оформление в Git (ветки, PR, прохождение code review)

## Требования
Требуется написать консольную утилиту «Погодный дайджест» на Node.js.

Утилита принимает название города (или список городов), получает по нему прогноз погоды из открытого REST API, выводит результат в читаемом виде в терминал и сохраняет отчёт в файл.

При любых сбоях — неверные аргументы, неизвестный город, недоступность сети, ошибка на стороне API — утилита должна завершаться корректно и сообщать пользователю понятную причину.

Используется открытый API Open-Meteo, ключ доступа не требуется:

**1.​ Геокодинг — получение координат по названию города:**
```JS
GET
https://geocoding-api.open-meteo.com/v1/search?name={город}&count=1&language=ru&format=json
```

**2.​ Прогноз погоды по координатам:**
```JS
GET
https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}&daily=temperature_2m_max,temperature_2m_min,precipitation_sum&forecast_days={n}&timezone=auto
```

По согласованию с наставником допускается другой открытый API (курсы валют, GitHub API и т. п.) при условии, что сохраняется цепочка из двух связанных запросов и выполняются все требования ниже.

## Функциональные требования

1.​ Запуск утилиты выполняется командой вида:
```bash
node src/index.js --city "Нижний Новгород" --days 3
```
2.​ Параметр --city обязателен и поддерживает несколько городов через запятую. Параметр **--days** необязателен, по умолчанию 3, допустимый диапазон 1–7.

3.​ Для каждого города сначала выполняется запрос геокодинга, затем — запрос прогноза по полученным координатам.

4.​ Города обрабатываются параллельно. Ошибка по одному городу не должна прерывать обработку остальных.

5.​ В консоль выводится: название города, страна, координаты и таблица по дням — дата, минимальная и максимальная температура, суммарные осадки.

6.​ Отчёт сохраняется в файл reports/{город}-{ГГГГ-ММ-ДД}.json.7 Кэширование: если отчёт по городу за текущую дату уже сохранён, данные берутся из файла без обращения к сети. Флаг --no-cache принудительно выполняет запрос заново.

8.​ Обрабатываются как минимум следующие ситуации: отсутствующий или некорректный аргумент; город не найден (пустой результат геокодинга); ответ со статусом 4xx; ответ со статусом 5xx; отсутствие сети; превышение таймаута; некорректный JSON в ответе.

9.​ Код завершения процесса: **0** — успех, **1** — ошибка.
